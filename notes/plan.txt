Diagnosis
Your classifier is over-recall: TPR=0.96 vs TNR=0.67. 427 FPs vs 49 FNs — almost 9:1. That ratio is the whole story:

The trainer already picks composite-optimal threshold (0.44).
fn_weight=fn_penalty=1.0 — symmetric loss is in effect.
200-tree depth-3 GBT with 33 base features + 33 unigram features is plenty of capacity.
So the residual error isn't a tuning problem; the feature set lacks negative-discriminative signal at the decision boundary. Almost every existing feature (gloss_match, cos_pct, cn_hops, usf_*, sv_*, base_similarity, model_*) ranges from 0 ("no evidence") to "strong evidence of relatedness." There's almost no signal that pushes scores down. So borderline pairs accumulate weak positive votes from noisy similarity sources and tip over the threshold.

That diagnosis directly implies the highest-leverage moves.

Tier 1 — high ROI, low effort (each ~hours, expect 3–8pp combined)
1.1 Run an FP error analysis first. Before adding anything, dump the 427 FPs grouped by which feature was strongest, and by cue. I'd bet ~70% of FPs cluster into a handful of failure modes (NB-cosine false friends, CN-hub bleed, polysemy). This tells you which of the proposals below to do first. Half a day, foundational.

1.2 Add explicit negative-evidence features. All of these are cheap:

pos_disjoint — 1 if word_a's POS set ∩ word_b's POS set is empty (you already compute pos_count).
min_cn_degree, min_usf_out_degree — currently you only have min/max via reductions, but a feature like log(min_cn_degree) tells the model "even the less-connected word is hub-y" → spurious connections.
freq_band_gap — |log_freq_a − log_freq_b|. Common-cue × rare-candidate pairs are usually unrelated in practice.
sense_disagreement — sv_max − sv_mean. High = "one sense matches, most don't" → classic polysemy FP.
dominant_sense_cos — cosine of word_a's most-frequent sense vector vs word_b's most-frequent. Strips polysemy when one obscure sense pulls sv_max up.
Adding 4–5 features and retraining is ~1 day. These are exactly the signals GBT can't reach with reductions alone.

1.3 Random-pair negative oversampling. Currently you have 1315 hand-curated negatives — almost all near-positives. The classifier never sees "obvious unrelated" examples, so its prior leans positive. Sample 5–10k random (common_preferred, common_preferred) pairs filtered to those not in any cue's precompute row, label them all unrelated, weight at e.g. 0.2 each. Should pull TNR up several points without hurting TPR much. ~1 hour to implement.

1.4 Isotonic calibration on top of GBT probabilities. Train a one-dimensional monotone regression on (predicted_prob → empirical positive rate) using the 2547 labeled rows via 5-fold CV. Often gives 1–3pp on its own and "fixes" the threshold-search problem permanently. ~2 hours.

Tier 2 — bigger lift, larger upside (~days each, 5–10pp range)
2.1 Cross-encoder gloss similarity feature. You already load MPNet sense vectors. Compute the sentence embedding of each word's primary gloss once at dict-build time, save to msgpack, and add gloss_cross_cos as a feature. MPNet on glosses is the gold standard for word-relatedness benchmarks; I'd expect this single feature to be the largest single-shot accuracy gain available. The fact that it's not currently in LEARNED_FEATURE_NAMES is the biggest gap in the feature set IMO.

2.2 Two-stage decision with a borderline reranker. Most of your error is in prob ∈ [0.35, 0.55]. Run the GBT first, then for borderline pairs only, apply a more expensive precision-focused stage:

Cross-encoder cosine (from 2.1)
A short rule sheet derived from 1.1 (POS disjoint → reject; hub bleed → reject; etc.)
Optionally: an LLM judge call on the ~5% borderline pairs, cached offline.
Borderline-only means you eat the cost on ~hundreds of pairs, not millions; the precompute already supports a second pass.

2.3 Targeted hard-FP active learning. Uncertainty sampling near threshold helps fill the queue. Add a complementary mode: sample pairs where the classifier is highly confident "related" (score 70–90) on words not covered by any prior cue. The TP/FP mix among those reveals where the classifier is over-confident — every FP you find there is a triple-strong negative training example. This complements your current tagging effort rather than competing with it.

Tier 3 — adjuncts (don't expect headlines)
Composite-objective rebalance. If user-facing harm is "too many bad rhymes" rather than "missing rhymes", train with --fn-weight 0.7 to push the classifier conservative. This is threshold tuning expressed in training-loss space; it doesn't add discriminative power.
Audit whatever-tagged rows. 286 are skipped. A pass to relabel any that are actually "unrelated" or "related" gets you "free" data.

My recommendation
Start with 1.1 + 1.2 + 1.3 + 1.4 in that order — that's about 2–3 days of work and should give you a 5–8pp bump without architectural changes. Then add 2.1 (gloss cross-encoder) for the next 5–8pp. By that point you should be close to or past 90%, and you'll have learned which Tier-2 directions matter for the residual errors.

I'd specifically not start with more feature crosses, more trees, or threshold-only tuning — your trainer has already extracted those gains, and the residual error is feature-coverage-shaped, not model-shape-shaped.
